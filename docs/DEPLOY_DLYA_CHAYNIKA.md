# Запуск игры для ВК «для чайника»

Здесь — **очень простыми словами**, что настроить, чтобы работали **онлайн**, **поиск живого соперника** и **сохранения** (всё это идёт через **API** на сервере).

---

## 1. Два слова: что не так «из коробки»

- **Сайт без сервера** (только картинки и HTML на GitHub Pages и т.п.) **не умеет** хранить очередь матчей и «кто онлайн». Это делает **программа на сервере** — в нашем проекте это **Next.js с папкой `app/api`**.

- Игра в ВК открывается **внутри ВКонтакте** (как страница в рамке). Браузер **проверяет правила безопасности**: если фронт с одного адреса, а данные с другого — на сервере нужно разрешить **CORS** (ниже есть готовая строка).

**Вывод:** нужен **хостинг с Node.js**, куда вы зальёте проект и запустите его как **один сайт** (и страницы, и `/api/...`). Так проще всего — **не нужен** отдельный `NEXT_PUBLIC_API_BASE_URL`.

---

## 2. Рекомендуемый путь: один сервер = один адрес

Идея: у вас есть адрес вида **`https://igra.vash-site.ru`**. И игрок заходит в ВК по этому адресу, и запросы к API идут на **тот же** адрес.

### Шаг 1. Взять VPS

- Любой провайдер (Timeweb, Selectel, DigitalOcean, Hetzner…).
- **Ubuntu 22.04** (или 24.04) — удобно для инструкций.
- Минимум **1 ГБ RAM** (лучше 2 ГБ).

### Шаг 2. Подключиться к серверу

На своём компьютере открываете **Терминал** (Mac/Linux) или **PowerShell** (Windows) и заходите по SSH (логин и IP даст хостинг):

```bash
ssh root@ВАШ_IP
```

Дальше команды выполняете **на сервере**.

### Шаг 3. Поставить Node.js (если ещё нет)

Проверка:

```bash
node -v
```

Если команды нет — поставьте **Node 20 LTS** (инструкцию «Node.js Ubuntu» легко найти в интернете; или через `nvm`).

Нужны также **git** и **pnpm**:

```bash
apt update && apt install -y git
npm install -g pnpm
```

### Шаг 4. Склонировать проект

```bash
cd /var/www
git clone https://github.com/ВАШ_ЛОГИН/rps-vk-game.git
cd rps-vk-game
pnpm install
```

(Если репозиторий приватный — настроьте ключ SSH или токен у GitHub.)

### Шаг 5. Файл с настройками `.env` на сервере

В папке проекта создайте файл **`.env`** (можно скопировать с примера):

```bash
cp .env.example .env
nano .env
```

**Обязательно проверьте / заполните:**

| Переменная | Что значит | Пример |
|------------|------------|--------|
| `NEXT_OUTPUT_EXPORT` | Должно быть **`0`** — тогда работает API | `NEXT_OUTPUT_EXPORT=0` |
| `NEXT_PUBLIC_VK_APP_ID` | ID мини-приложения из кабинета ВК | число из настроек приложения |
| `VK_APP_SECRET_KEY` | Секретный ключ приложения ВК (только на сервере!) | из кабинета ВК |

**Для схемы «один домен»:**

- **`NEXT_PUBLIC_API_BASE_URL` — не пишите** (или оставьте пустым). Так игра сама ходит на `/api/...` на том же сайте.

**Папка для данных игроков и очереди** (чтобы не было ошибок прав):

```bash
mkdir -p /var/rps-data
chown -R $USER:$USER /var/rps-data
```

В `.env` можно явно указать (пути могут отличаться — главное, чтобы папка существовала и была доступна на запись):

```env
PLAYERS_DB_PATH=/var/rps-data/players.json
GAME_STATE_DB_PATH=/var/rps-data/game-state.sqlite
```

Если `PLAYERS_DB_PATH` не задавать, в проде проект по умолчанию тоже смотрит в `/var/rps-data` — папка всё равно нужна.

Сохраните файл в nano: **Ctrl+O**, Enter, **Ctrl+X**.

### Шаг 6. Собрать и запустить

```bash
pnpm run build
pnpm start
```

По умолчанию сайт слушает порт **3000**. Проверка с сервера:

```bash
curl -s http://127.0.0.1:3000/api/presence/online-count
```

Должен прийти JSON с `"ok":true` (или похожий ответ без ошибки HTML).

**Чтобы сервер не выключался**, когда вы закроете SSH, используйте **PM2**:

```bash
npm install -g pm2
pm2 start pnpm --name rps -- start
pm2 save
pm2 startup
```

(Последняя команда покажет ещё одну строку — её нужно один раз выполнить от root.)

### Шаг 7. Домен и HTTPS (чтобы ВК открыл приложение)

ВК требует **HTTPS**.

1. В панели домена пропишите **A-запись** на IP вашего VPS.
2. На сервере поставьте **Nginx** как «витрину» и **Certbot** для бесплатного сертификата Let’s Encrypt.

Кратко: Nginx принимает `https://igra.vash-site.ru` и **проксирует** на `http://127.0.0.1:3000`. Точные команды зависят от дистрибутива — в поиске: **«nginx reverse proxy node pm2 certbot»**.

### Шаг 8. Настройки мини-приложения ВК

В [настройках приложения ВК](https://vk.com/apps?act=manage):

- **URL приложения** (или адрес для мини-приложения) — ваш **`https://igra.vash-site.ru`** (если приложение в подпапке — с путём, например `https://site.ru/rps`, и тогда в `.env` нужен `NEXT_PUBLIC_BASE_PATH=/rps` **и при сборке**).

Сохраните, подождите пару минут, откройте приложение в ВК с телефона и ПК.

## 3. Если фронт лежит отдельно (GitHub Pages и т.д.)

Это **сложнее**: статический сайт не имеет API, поэтому:

1. На **VPS** крутится полный Next с **`NEXT_OUTPUT_EXPORT=0`** (как выше) — это ваш **бэкенд**, например `https://api.vash-site.ru`.

2. При **сборке статики** на компьютере или в GitHub Actions в `.env` перед `build`:

   ```env
   NEXT_OUTPUT_EXPORT=export
   NEXT_PUBLIC_API_BASE_URL=https://api.vash-site.ru
   ```

   Без `/` в конце. После смены URL — **пересобрать** фронт заново.

3. На **VPS** в `.env` добавьте **CORS** (чтобы ВК разрешил ответы):

   ```env
   CORS_ALLOWED_ORIGINS=https://web.vk.com,https://vk.com,https://m.vk.com,https://vk.ru,https://ВАШ-username.github.io,https://*.github.io
   ```

Если не уверены — **лучше не делайте так**, а используйте **один домен** (раздел 2).

---

## 4. Как понять, что всё заработало

1. В браузере откройте:  
   `https://ВАШ-ДОМЕН/api/presence/online-count`  
   Должен быть **JSON**, не страница с ошибкой.

2. В игре в ВК на экране выбора «Живая игра» при **неделе босса** снова появится строка **«N онлайн в игре»** (если API отвечает).

3. Два аккаунта в поиске с **одинаковой ставкой и режимом** должны чаще находить друг друга (очередь на сервере в SQLite).

---

## 5. Если что-то не работает

| Проблема | Что сделать |
|----------|-------------|
| Белая страница / 502 | Проверьте `pm2 status`, логи: `pm2 logs rps` |
| В ВК пусто или ошибки сети | Проверьте **HTTPS** и правильный **URL** в кабинете ВК |
| `501` или `no_server` в ответе API | На сервере **`NEXT_OUTPUT_EXPORT=0`**, пересоберите `pnpm run build` |
| В консоли браузера **CORS** | Нужен **`CORS_ALLOWED_ORIGINS`** на бэкенде (актуально для «двух доменов») |
